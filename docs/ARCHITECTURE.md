# アーキテクチャ

## 全体像

```
┌────────────────────────── Mac（常駐する「脳」）──────────────────────────┐
│  server.mjs（Node標準ライブラリのみ・依存ゼロ）                          │
│    GET  /api/info   → LANアドレス・モード情報                             │
│    GET  /api/state  → { updatedAt, payload }                             │
│    PUT  /api/state  → 原子的にJSONへ保存                                 │
│    .spinalix/brain.json ← 記憶の全データ（断片・回路・想起・結晶・採否）  │
└──────────────┬───────────────────────────────────────────────────────────┘
               │ 同一Wi-Fi（QRコードで接続）
┌──────────────▼───────────────┐   ┌────────────────────────────────┐
│ スマホ（PWA・Safari）         │   │ ブラウザUI（Mac/スマホ共通）    │
│  同じUI・同じ記憶             │   │  ホーム / 回路 / 目的           │
└──────────────┬───────────────┘   └──────────────┬──────────────────┘
               └───────────┬──────────────────────┘
                    記憶エンジン（src/lib・純関数）
```

- サーバーがいる環境: 変更は `PUT /api/state` でMacのJSONに保存。他端末は6秒間隔の `GET` で取り込む（最終更新優先）。
- サーバーがいない環境（GitHub Pages等）: `localStorage` に保存する「判定用モード」へ自動フォールバック。機能は同一。

## 記憶エンジン（src/lib/engine.ts）

すべて純関数・決定論的（同じ入力 → 同じ出力）。乱数を使っていないため、テストが可能で、動画の再現撮影もできる。

### 1. 自動回路 `buildLinks(fragments)`

断片の全ペア（O(n²)、100断片程度では十分軽量）について6種類のリンクを生成:

| 種類 | 意味 | 判定 |
|---|---|---|
| `similar` | 近い記憶 | 文字バイグラムのJaccard × 感情類似度 |
| `echo` | 反響 | 支配感情が同じ + 21日以上離れている + 感情が近い + 言葉は遠い |
| `tension` | 矛盾 | 同一テーマ + 感情valenceが0.85以上反対 + 14日以上離れている |
| `recall` | 自己引用 | 「」で括られた語句が、過去の断片の本文に実在する |
| `theme` / `person` | テーマ/人の共有 | タグ/人名の一致 |

ノードごと・種類ごとの上限（recall 2, echo 2, tension 2, similar 3, theme 2, person 2）→ ノードごと上位8本に絞る。**「少数精鋭」でないと矛盾はノイズになる**という設計判断。

### 2. 想起生成 `generateSuddenThought(...)`

- 候補 = `recall` / `tension` / `echo` の未使用リンク。
- スコア = リンク重み + 種類ボーナス + 採否学習バイアス − 使用済みペナルティ − 同種連続ペナルティ。
- テンプレートで文を合成（種類ごとに2〜3種を使い分け、日付・引用を差し込む）。
- 候補が尽きたら「問い」型（テーマの反復回数から疑問を立てる）。
- **採否学習**: 「これは私だ / ちがう」の累積が次回のスコアに反映される。

### 3. 思考結晶 `assembleCrystal(intention, ...)`

目的（問い）に対して: 想起（重み付き選抜・whyラベル付き）→ 感情の弧（月次バケット・前半/後半比較でラベル）→ 洞察（反復・人物・行動語の統計から決定論的に生成）→ 矛盾（テーマ内で最大の振れ幅ペア）→ 次の一歩。

## 感情モデル（src/lib/emotion.ts）

8感情（喜び/愛おしさ/期待/静けさ/悲しみ/不安/怒り/疲れ）の強度ベクトル + valence（快-不快）/ arousal（静-動）。日本語の語彙パターンと強調語（とても/めっちゃ等）から推定。アプリ上の感情チップは手動補正として合成される。外部APIなし。

## テスト

`src/lib/engine.test.ts` — ペルソナ実データに対する検証:
- 自動回路が6種を生成する / 仕込んだ自己引用・矛盾ペアが実際に検出される
- 想起は出典を持つ / 同じペアを再利用しない / 決定論的
- 採用された想起が回路に定着する / 思考結晶が出典つきで返る
- 感情語彙の推定（正/負）

## UI（src/components）

- Canvas + d3-force による回路ビジュアル（感情色ノード・6種リンク・想起時のパス発火・パン/ズーム/タップ）
- 想起カード、目的モード、捕獲シート、断片詳細（つながった記憶の探索）、設定（QR接続・エクスポート・リセット）

## 主要な技術判断

- **外部AI APIを使わない**: 審査員がキーなしで全機能を試せることを最優先。LLMは「文章の質」のためでなく、「構造の発見」と「決定論的再構成」で価値を出す設計。
- **Canvas描画**: 100断片・300リンクでも60fps。DOM/SVGでは重い。
- **相対パスビルド（base: './'）**: GitHub Pages配下でも壊れない。
