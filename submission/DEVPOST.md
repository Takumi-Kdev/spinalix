# Devpost 提出文（コピペ用）

## 名称
Spinalix

## タグライン（200字以内）
断片（感情つきの一行）を貯めると、AIが記憶回路を自動で組み、あなたの中から「ふとした想起」を生成して、思考と決断という成果物に変える、ローカル完結の思考脳。

## Inspiration

メモは貯まるのに、二度と読み返されない。チャットAIの答えは抽象的で、自分ごとにならない。
問題は、記憶が足りないことではなく、**自分の記憶が使われないこと**でした。

既存の「AIメモリー」は保存と検索です。人間の想起は、問いを必要としない。それならば、**システムの側から想起を届ける**記憶を作れないか——Spinalixはそこから始まりました。

## What it does

- **想起の生成**: 感情つきの断片から、AIが6種類の記憶回路（自己引用/矛盾/反響/近さ/テーマ/人）を自動で張り、毎日「ふと」を提示します。すべての想起には出典（いつ・どの断片から生まれたか）が付きます。
- **矛盾の指摘**: 同じテーマで感情の向きが正反対の記憶（例: 5月の「諦めたほうがいい」と10月の「明日、出す。」）を、忖度せず提示します。
- **思考結晶（目的モード）**: 「留学に行くべきか、迷っている」と書くと、8ヶ月分の断片から、出典つきの想起・感情の弧・洞察・矛盾・次の一歩を組み上げます。
- **採否学習**: 「これは私だ / ちがう」の選択だけが回路に定着し、次の生成に反映されます。
- **ローカル完結**: Macに常駐する「脳」（Node標準ライブラリのみ）にスマホがQRひとつで接続。感情データは外部に送信されません。

## How we built it

- TypeScript + React + Vite + Tailwind CSS（UI）、d3-force + Canvas（回路ビジュアル）、zustand（状態）
- 記憶エンジンは**純関数・決定論的**（`src/lib/engine.ts`）: 全ペアのリンク計算 → 種類ごとの上限 → 想起の生成（テンプレート合成 + スコア + 採否学習）→ 思考結晶の組み上げ
- 感情モデル（`src/lib/emotion.ts`）: 日本語語彙から8感情ベクトル・valence/arousal を推定。**外部AI API不使用**（キーなしで誰でも全機能が動く）
- Mac常駐サーバーは Node 標準ライブラリのみ（依存ゼロ）で、`.spinalix/brain.json` に原子的に保存。静的環境では localStorage に自動フォールバック
- テスト: ペルソナ実データに対する12件の検証（仕込んだ自己引用・矛盾ペアの検出、出典の実在、決定論性など）

## Challenges we ran into

1. **「読み物」ではなく「回路」にする難しさ**: 初期の実装はリンクが多すぎて、矛盾がノイズになりました。ノードごと・種類ごとに上限を設け、「少数精鋭」に絞る設計に変えて解決。
2. **捏造しない生成**: LLMに自由に書かせず、実在の断片の引用と日付だけで文を合成する仕組みにしました。品質と「Google無しで動く」ことのトレードオフを、テンプレートの作り込みで埋めました。
3. **開始型UI**: 通知や依頼ではなく「開いた瞬間に想起が届いている」体験の設計。多重生成や同種の連続を防ぐスコアリングを実装しました。

## Accomplishments that we're proud of

- 8ヶ月分の記憶（64断片・265回路）から、**意図的に仕込んだ自己引用と矛盾を、エンジンが実際に発見する**ことをテストで証明
- 外部AI APIなしで、想起の生成から思考結晶までが完全に動作（審査員がキーなしで試せる）
- Mac常駐 + スマホのQR接続による「自分の記憶は自分の手元に」の実装
- 倫理の実装: 出典の強制・忖度しない・通知は1日2回まで・JSONエクスポート

## What we learned

- 「AIによる記憶」の本質は保存ではなく**再結合と選択**であること
- 感情を第一級データにすると、検索では出てこないつながり（遠い時期の同じ感情、向きの違う発言）が見つかること
- 決定論的なエンジンでも、入力（断片の質）と採否（人間の選択）次第で、驚くほど個人的な出力になること
